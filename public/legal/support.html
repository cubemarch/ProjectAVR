AVR Capture — Support

Last updated 21 September 2026

AVR Capture turns an iPhone into a live video contribution encoder. It records with one or both rear cameras and sends the result to a server address you provide.

Getting started

  1. Open Settings and add a destination — the address and port of the server that will receive the broadcast.
  2. Enter the stream key for that destination. It is kept in the iOS Keychain and is never shown again.
  3. Tap Test connection to confirm something is listening. This does not send the key, because a key may be valid for a single broadcast and spending one on a test is not a test.
  4. Confirm the broadcasting terms, then go live.

A server can also issue a destination link, which fills in the address, port and key in one step. The app always shows you what a link contains and asks you to confirm before it saves anything.

Common problems

"Nothing is listening on that port"
The address was reached but nothing answered. Check the server is running and that the port matches.
"Could not reach that address"
Usually the phone and the server are on different networks. A private address — anything starting 192.168., 10. or 172.16–31. — is only reachable over Wi-Fi, and the app will not try to reach one over cellular.
"Local network access is denied"
iOS requires explicit permission before any app may connect to an address on the same Wi-Fi. Turn it on in Settings › Privacy & Security › Local Network.
"The server did not accept this destination's key"
Some servers issue a key that is valid for one broadcast and expires in minutes. If yours does, request a new destination link and import it. The app stops rather than retrying, because a key that has been refused once will be refused again.
"The server's certificate is not the one this destination expects"
The destination was set up to accept one specific certificate and the server presented a different one. If the server was reinstalled or its certificate regenerated, import a new destination link. If nothing on the server changed, do not go on air — something is answering in its place.
Only one camera is used
Stereo capture needs two rear cameras running at once, which not every iPhone supports, and iOS will stop a two-camera session when the device gets hot. Diagnostics reports what this device can do and what it is currently doing.
The broadcast has no sound
Check the Sound switch in Settings; it is on unless someone turned it off. iOS asks for the microphone the first time you go live with it on, and if that was declined, Settings shows a row that takes you straight to the iOS permission. Diagnostics reports whether sound was requested, whether a microphone is connected, and how many audio buffers have been encoded — if the third is zero while the second says yes, something else on the device has taken the input. Note that a receiving page may also start muted: browsers do not allow sound to begin without a click, so check the receiver's own control before changing anything on the phone.
The picture stutters or the app reports dropped frames
The link cannot carry the bitrate. The app drops frames rather than queue them, because a stream that skips is still live and a stream that lags is a slow recording. Lower the bitrate in Settings or move closer to the access point.

Reporting a problem

Diagnostics in the app produces a report describing the device, the capture session and the connection. It contains no stream keys and no full server addresses. Attaching it makes almost any report faster to answer.

Privacy

The app collects nothing and contains no analytics or third-party code. See the privacy policy.
